# Phase 0: Discovery and baseline

Date: 2026-09-28. No behaviour changes.

## Repo map

- **Build:** Vite 6 with `vite-plugin-singlefile`, rooted at `src/web`. A custom plugin in `vite.config.ts` swaps the CSP meta tag and the `__HRIS_PRODUCTION__` placeholder. `npm run build` writes `dist/index.html` and copies it to `dist/hris-reconcile.html`. Rebuilding produces exactly the committed file.
- **Worker:** `src/web/reconciliation.worker.ts`, bundled with Vite's `?worker&inline`.
- **Test runners:**
  - Vitest in a `node` environment. There is no DOM environment, so UI tests must be Playwright tests.
  - Playwright runs on Chromium, Firefox and WebKit against the built `dist/hris-reconcile.html`.
  - pytest covers the Python app.
- **Runtime dependency:** `papaparse` is the only one.

## Where the codebase differs from the plan

1. **A Python version of the same engine is used as a test reference.** `src/hris_reconcile` is a Python implementation that also drives the Windows `.exe`. Two web tests depend on it:
   - `differential.test.ts` compares browser output to CSV/JSON generated by the Python version.
   - `parity.test.ts` checks the web JSON report against the Python report schema (`extra="forbid"`).

   Several current behaviours exist only to match Python: rejecting a repeated alias within one entry, the Python whitespace set, and the casefold table. Phases 1 and 4 (`MISSING_IDENTITY`, grouped mappings, NFC, new report metadata) will break these tests by design.
2. **The CSV parser is PapaParse plus custom code.** Phase 3 error codes (`CSV_ROW_WIDTH` etc.) will wrap PapaParse errors.
3. **`<missing>` is embedded in the data path.** `main.ts:108` `display()` turns null into `"<missing>"`, and that display string is saved as the alias (`left_display`). `confirmMappings` then rejects the literal `"<missing>"` (lines 663–664). Fixing 1.2 means changing the editor's data model, not just the aggregation keys.
4. **Sort order:** `localeCompare` appears 9 times (results analysis, mapping analysis, suggestions). Identity order, duplicate headers and missing columns use `.sort()` (UTF-16 code unit, not code point). All will move to the shared comparator.
5. **The `data:` worker fallback comes from Vite's `?worker&inline` wrapper**, not app code. Removing it means replacing that import with a small custom plugin that inlines the worker source and creates a Blob URL.
6. **The `"true" !== "true"` guard comes from the inline script in `src/web/index.html`.** It shows "open the built workbench" when the source HTML is opened directly, and a browser test covers that. Strip it only from the production build.
7. **Profiles are computed three times.** `suggestIdentity` and `scoreIdentityPair` recompute `profileDataset` after the `parse` handler already did. `normalizedValues` is rebuilt for every column pair (`suggestions.ts:155`). Confirms item 3.2.
8. **Worker crash handling is incomplete.** `worker_client.ts:58` rejects pending requests and drops the worker but keeps main-thread `state`, producing stale "upload the left dataset first" errors.
9. **Summary-first results (3.3) reach further than planned.** `full.csv` includes every matching comparison, so that export must also be recomputed from the datasets and contract.
10. **One data-keyed map uses a plain object.** `FIELD_ALIASES` in `suggestions.ts` is indexed by a key built from headers. It can't hit a prototype key (every key contains `|`), but it breaks the `Object.create(null)` rule. Switch to a `Map` in Phase 1.

## Open questions

1. **Python parity:** change the Python engine the same way, or freeze Python as legacy, regenerate/retire the differential fixtures, and give the web report its own `format_version` (e.g. `2.0`)? Recommendation: freeze and version.
2. **Scope:** Python UI and Windows `.exe` out of scope?
3. **Blank identities:** should whitespace-only count as `MISSING_IDENTITY`? The parser only turns `""` into null today. Proposal: null or all-whitespace; raw value kept otherwise.
4. **Engine version:** `package.json` says `1.0.0`; the report hard-codes `0.3.0` (matches `pyproject.toml`). Phase 4 will read `package.json`, so reports will say `1.0.0`. Correct?
5. **UI tests:** write Phase 5 UI tests in Playwright, or accept `happy-dom` as a development-only dependency (not shipped in the build)?
